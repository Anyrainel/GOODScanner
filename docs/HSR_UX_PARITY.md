# 原神与星穹铁道的桌面体验对照

更新：2026-10-08。以下为实际实现范围，自动测试不代表实机游戏操作已经验证。

## 已对齐的管理器流程

1. 桌面管理器设置端口并启动连接，空闲时等待网站请求，不要求选择指令文件。
2. GGStarRail 遗器整理页连接本机管理器、准备操作预览，用户点击「应用到游戏」才提交。
3. 桌面与网站显示同一个任务的类型、数量、实际步骤、进度和结果。
4. 现有星铁引擎负责完整库存重扫、唯一匹配、重新读取、点击后验证和持久恢复记录。
   恢复原任务不伪装成一次新的库存重扫，也不会盲目重复上次点击。
5. 网站取得逐项结果，只回写已验证且仍唯一匹配的锁定／弃置状态。
   任务期间更换或修改账号时，提示当前账号未更新，保留游戏操作结果。
6. 停止任务不关闭连接；停止连接会先取消当前任务，再结束 HTTP 服务。
   冲突请求被拒绝，重复的已完成请求不会重新执行，失败任务允许显式重试。

代码：`application/src/hsr_server.rs` 为轻量 loopback 传输层；
`gui/star_rail_worker.rs` 复用实际扫描与管理引擎；
GGStarRail 的 `scannerManager.ts`、`ScannerManagerConnection.tsx` 提供发送、轮询与结果 UI。
协议见 [HSR_MANAGER_API.md](HSR_MANAGER_API.md)。

管理器的 HDR、延迟与开拓者设置与扫描页共用组件和配置。
开拓者信息仅在请求角色扫描时必需，遗器管理不会提前显示缺失警告。
恢复路径继续兼容已有配置，普通界面不展示 JSON、摘要和逐类授权复选框；
旧 CLI 精确计划确认方式仍保持独立、有效。

## 共用的桌面体验

游戏切换、语言、窗口、分割布局、日志、错误提示、任务进度行、刷新数据、
抓包阶段帮助均已共享。原神和星铁抓包页不再堆放静态使用说明；
启动、登录、等待数据、打开成就、导出、停止和失败按实际阶段显示。

导出无需选择文件夹。默认使用程序目录，既有自定义导出位置继续生效。

## 仍有差异的能力

| 项目 | 星铁当前范围 |
| --- | --- |
| 管理操作 | 支持锁定／解锁、弃置／取消弃置；整理页按既有策略生成保护性操作，不自动分解 |
| 远程扫描 | HTTP `POST /scan` 支持角色、光锥、遗器；结果返回 HSR-Scanner v4 导出；网站的远程扫描导入入口尚未加入 |
| 装备／卸下 | 尚无星铁游戏操作实现，接口不会声称支持 |
| 扫描导出策略 | 尚未增加原神侧的停止时保存和仅保留最新导出选项 |
| 抓包导出默认 | 仍保留原先用户设置及旧默认，不强行改写 |

光锥、遗器、位面饰品、开拓者、行迹、星魂、叠影、弃置标记，以及各自
坐标、协议、匹配字段和导出格式是合理的游戏差异，不混用 GOOD 数据模型。
